# Python reference producer

The smallest producer that is honestly a producer: a configuration defined as dataclasses, a module
deriving the contract from those types, and the document it emits, committed. It exists to prove
the claim [`PRODUCER.md`](../../PRODUCER.md) is built on — that a new language's whole obligation is
a document `terrace-contract conform` accepts — with nothing behind it but the standard library.

It is a teaching artefact, not a library to depend on. Copy the shape, not the module.

| File | What it is |
|---|---|
| [`orders.py`](orders.py) | The service's configuration types, mirroring [`rust/examples/service/config.rs`](../../../../rust/examples/service/config.rs) and [`java/terrace-config-example-service`](../../../../java/terrace-config-example-service) field for field. |
| [`terrace_producer.py`](terrace_producer.py) | The derivation: types to keys, the dialect's spellings, the `json_schema` half, the envelope, the bytes. |
| [`contract.json`](contract.json) | What `orders.py` emits. Committed, and regenerated by the test on every run. |
| [`test_producer.py`](test_producer.py) | The committed bytes, the bytes under three hash seeds, and the tier 2 spellings against the corpus. |

Python 3.10 or later, no third-party package.

## Running it

From the repository root:

```bash
python3 spec/v1/producers/python/orders.py > spec/v1/producers/python/contract.json
python3 -m unittest discover -s spec/v1/producers/python

cli/target/release/terrace-contract conform --tier 2 spec/v1/producers/python/contract.json
cli/target/release/terrace-contract validate spec/v1/producers/python/contract.json
```

`conform` and `validate` print nothing and exit `0` on this document. The `producer (python)` job in
[`ci.yml`](../../../../.github/workflows/ci.yml) runs all four.

## Tier

**Tier 2.** Every spelling it publishes is the one the dialect derives, which is what
`conform --tier 2` checks for `env` and `env_file`, and what
[`test_producer.py`](test_producer.py) checks for every field the tier names — `env`, `env_file`,
`secrets_file`, the three alias lists and `unreachable` — against the corpus cases this type
vocabulary can express: [`minimal`](../../conformance/minimal/) and
[`unnameable-key`](../../conformance/unnameable-key/), the second being the case tier 2 exists for.

**Not tier 3.** Tier 3 is byte-identity with another implementation over a shared case, and is
reachable only between implementations sharing a loader and a type mapping. This one shares
neither: its `ty` is `str` where the corpus says `String`, and its `producer.loader` is its own.
`conform --tier 3` accepts the document, because byte-identity is not a property of one document;
accepting is not meeting, and the claim stays at 2.

## Reads

`producer.loader` is `python-reference`, and no read table for it exists in
[`FORMAT.md`](../../FORMAT.md). That is deliberate and it is the one place this producer is smaller
than a real one: there is no loader behind it, so there is nothing to measure. The document
describes the layer model `FORMAT.md` defines — environment, `_FILE` indirection, a secrets
directory, a TOML document — and makes no claim about how text in any of them is parsed:

- no key carries `text_constraint`, because a pattern is a measurement and none was taken;
- every key carries `text_form`, which follows from the type alone;
- a consumer meeting the document skips the range step of
  [Reading a variable](../../FORMAT.md#reading-a-variable) and says so, as it does for
  [`foreign-loader`](../../conformance/foreign-loader/).

A producer for a real service does the opposite: it names the library it links, measures that
library's reads, publishes the patterns, and adds the table to `FORMAT.md`
([`CONFORMANCE.md`](../../CONFORMANCE.md#adding-an-implementation), steps 1 to 3).

## What the types can say

| Python | `ty` | `constraint` | `text_form` |
|---|---|---|---|
| `str` | `str` | `{"type": "string"}` | `text` |
| `int` | `int` | `{"type": "integer"}` | `integer` |
| `bool` | `bool` | `{"type": "boolean"}` | `boolean` |
| an `enum.Enum` with string values | its class name | `{"enum": [...], "type": "string"}` | `choice` |
| a dataclass | none: a table, whose fields are keys | | |
| `X \| None` | as `X` | as `X` | as `X` |

An `int` carries no bound, because a Python `int` has none to state. Any other type is refused
rather than described as `unknown`.

What a type cannot say is `dataclasses.field` metadata, written through three helpers: `setting`
(a key with a default, optionally `secret`), `required` (a key with none) and `table` (a nested
table). Python keeps no field docstrings at runtime, so the prose travels in the metadata too.

| Field | Derived from |
|---|---|
| `path` | field names, `.`-joined through tables, in declaration order |
| `env`, `env_file`, `secrets_file`, `unreachable` | the path and the dialect; `env: null` and `unreachable: unnameable` when the path does not survive the case fold |
| `default`, `default_value` | the default instance passed in, except for a secret, which publishes none |
| `required` | no default on the field and not `X \| None` |
| `json_schema` | the same keys, closed at every level, members in name order |

## Deliberately absent

Aliases, notes, refinements, sequences and maps, `schema.reload` and reserved keys. Each is a field
`FORMAT.md` defines and `conform` checks; none is needed to prove the claim, and each would add a
vocabulary to a module whose point is to be read in one sitting. The alias lists are always empty,
which is a true statement about these types rather than an omission.
